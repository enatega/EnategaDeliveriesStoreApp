Store App Operational Flow Guide

A client-facing overview of how the Enatega Deliveries Store App works, including store login, order flow, rider coordination, scheduled orders, wallet, earnings, profile controls, and the local setup points that matter for a successful deployment.

Application Scope

This mobile app is the store-side workspace used by merchants to receive, manage, prepare, and complete customer orders. It supports both delivery and pickup workflows, and it also includes rider coordination features such as rider status updates, pickup confirmation, and direct rider chat/call actions for live delivery fulfillment.

1. Executive Summary

The Store App is the merchant control surface for the delivery ecosystem. A store logs in with its store account, receives new orders in real time, accepts or rejects them, manages preparation timing, marks orders as ready, confirms rider pickup where needed, and tracks completion through live status updates.

The app is built around five operational pillars: authentication and session control, order management, rider communication, financial tracking, and store profile settings. These pillars work together so that day-to-day store operations happen in one place.

2. Primary User Flow

1

Login & Session Start

The merchant logs in using store credentials. On successful authentication, the app stores the access token securely and switches from the login flow to the main operational workspace.

2

Main Workspace Opens

The user enters a four-tab interface: Orders, Wallet, Earnings, and Profile. This is the primary operating environment for the store.

3

Orders Arrive in Real Time

A live socket connection listens for new orders and order status changes. New orders appear at the top of the list without needing the user to manually refresh.

4

Store Processes the Order

The store can accept or reject orders, set preparation timing, move orders through ready and pickup states, and follow delivery completion status.

5

Rider Coordination Continues the Fulfillment Flow

For delivery orders, the app receives rider assignment and rider status updates. The store can also open rider chat or initiate a phone call where rider details are available.

6

Financial Tracking & Settings Remain Available

At any time, the store can review wallet balance, request withdrawals, track earnings, update schedule, manage bank details, change language, and adjust availability or instant delivery behavior.

3. Module-by-Module Working Flow

Module Purpose How It Works in Practice
Authentication Controls secure login and session startup. The app logs in through the store email endpoint, stores the token securely, restores the session on app restart, and automatically sends the user back to login if the backend reports session expiry.
Orders Central workspace for new, active, ready, pickup, completed, and scheduled orders. Orders are loaded through dedicated APIs and shown in status-based tabs. The store handles order actions from the order cards, not from separate admin pages.
Real-Time Sync Keeps store order data current without manual refresh. A socket connection is opened after login. It listens for new orders, order status updates, rider status changes, and chat messages. Relevant order tabs are refreshed or updated automatically.
Rider Coordination Supports live delivery-side collaboration. Delivery flows include rider assignment, rider progress updates, rider chat, and direct phone call launch when rider details are available.
Wallet Shows store balance, recent transactions, and withdrawal handling. The wallet module fetches current balance, available withdrawal amount, pending requests, and transaction history. The store can submit a withdrawal request directly from the app.
Earnings Presents business performance and earning activity. The app displays a chart view, daily earnings activity, summary drilldowns, and order-based earning history for selected dates.
Profile & Operations Controls store availability and business settings. The store can toggle availability, configure instant delivery, edit profile contact details, set a work schedule, update language, and maintain bank data.
Localization Supports multilingual user experience. The app currently includes English and French language dictionaries and exposes a language selection screen in the profile area.

4. Order Lifecycle in Detail

4.1 New Order Stage

Orders first appear in the New Orders tab. The store can review the order details, line items, address type, customer notes, and total amount.

  • The store can accept the order.
  • The store can reject the order with a reason.
  • New orders can be filtered by delivery or pickup type.

4.2 In Progress Stage

Once accepted, the order moves into the operational preparation state. The store manages preparation timing here.

  • The store can update preparation time.
  • The UI keeps countdown-related data visible.
  • Rider assignment data starts becoming relevant for delivery orders.

4.3 Ready Stage

When preparation is complete, the order can move into the Ready stage. This indicates the store has finished preparing the order and it is ready for pickup or dispatch.

4.4 Pickup Stage

Pickup-related actions are handled in a dedicated tab. This is where rider arrival, rider status, and pickup confirmation become most important.

  • For non-instant pickup flow, the store can confirm pickup.
  • Rider progress states continue to update in real time.

4.5 Completed Stage

Delivered, cancelled, rejected, and failed outcomes are presented in the completed area so the store has a clear historical view of finalized order activity.

4.6 Scheduled Orders

Scheduled orders are available separately from the main immediate order tabs. This helps the store review upcoming workload without mixing it into live active orders.

5. Real-Time and Delivery Coordination Flow

Real-time behavior is one of the most important parts of this app. After login, the mobile app opens a socket connection using the authenticated store session. This allows the store to receive event-based updates rather than relying only on periodic refreshes.

Live Event Store App Behavior
New Order Created The order is inserted into matching New Order lists and the alert loop can be triggered.
Order Status Updated The app invalidates the relevant order tabs so the order appears in the correct stage.
Rider Status Updated The app refreshes active delivery-related tabs so the store sees the rider’s latest state.
Chat Message Received The message appears inside the rider chat thread and is merged with previously loaded messages.
Important client note: the delivery-side coordination in this app depends on the backend socket service, rider assignment logic, and chat services being available and correctly mapped to the store account and order records.

6. Wallet and Earnings Flow

Wallet

  • Shows current balance and amount available for withdrawal.
  • Shows pending withdrawal requests when present.
  • Displays recent transaction history.
  • Allows withdrawal requests directly from the app.

Earnings

  • Shows a graph summary for recent earnings.
  • Shows daily earnings activity with pagination.
  • Allows deeper earning detail by selected date.
  • Uses the central currency configuration for formatting.

7. Profile and Store Controls

The Profile area is operationally important because it gives the merchant control over store behavior, not just account details.

  • Availability toggle: marks the store as available or unavailable.
  • Instant delivery toggle: enables immediate delivery or a day-based delivery time setting.
  • Work schedule: defines active days and time slots.
  • Bank management: stores payout-related account information.
  • Language: allows the user to switch between supported languages.
  • Scheduled orders access: exposes future order planning as a separate screen.
  • Logout: clears the session and returns the app to the login flow.

8. Local Setup and Deployment Notes

The following items are important for local setup, QA, and client-side deployment validation.

Configuration Item Why It Matters
EXPO_PUBLIC_API_BASE_URL Required. The app will not boot without this backend API base URL.
EXPO_PUBLIC_SOCKET_URL Optional. If not provided, the socket origin falls back to the API origin.
EXPO_PUBLIC_SOCKET_PATH Optional. Defaults to /socket.io and must match the backend socket setup.
EXPO_PUBLIC_EAS_PROJECT_ID Used as a fallback for push token registration if not already available in Expo config.
google-services.json Required for the Android Firebase/notification configuration already referenced by the app.
Physical Device for Push Push token registration is intended for a real device. Simulator-only testing is limited.

9. Important Client Considerations

  • The app is dependent on backend auth, order, wallet, earnings, profile, chat, and socket services.
  • Real-time order and rider coordination will only work when the socket server is available and authenticated correctly.
  • Push notification registration is built into login preparation, but device permissions must be granted by the user.
  • Store users must have a valid store-linked profile in the auth response for store-specific real-time filtering to work correctly.
  • Wallet and earnings values are formatted using the central currency configuration returned by the backend.
  • The app currently includes English and French localization support.
  • Scheduled orders are intentionally separated from immediate operations to improve operational clarity.

10. Recommended Handover Checklist

  • Confirm production API base URL and socket URL/path.
  • Confirm store login credentials and store-profile mapping.
  • Validate real-time new order arrival and rider status events.
  • Validate order action permissions: accept, reject, ready, confirm pickup.
  • Validate wallet balance, transaction history, and withdrawal flow.
  • Validate earnings chart and date-based detail flow.
  • Validate bank management, work schedule, language, and availability controls.
  • Validate push-notification permissions on a physical Android/iOS device.

11. Closing Summary

In practical terms, this Store App is designed to be the merchant’s live operations console. It combines order intake, kitchen/store preparation flow, rider-side coordination, finance visibility, and store configuration into one mobile experience. For the client, the most important success factors are a stable backend connection, correct store account mapping, and fully working real-time services.

With those dependencies in place, the app provides a complete store-side workflow for both delivery and pickup operations, with the delivery side enhanced by live rider communication and status awareness.
